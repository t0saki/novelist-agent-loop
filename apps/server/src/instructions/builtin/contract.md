# 文件机制（由软件校验，不可被覆盖）

本节只规定文件怎么交付。写什么、怎么写，一律以作者指令和工作单为准。

1. 任务写在工作单（work order）里。frontmatter 列出的 `out_dir` 和产物清单就是你的交付清单。
2. 只在 `out_dir` 下写文件。写到其他位置的内容会被丢弃，不要修改书库中的其他文件。
3. 产物要与清单一一对应：路径正确，不多不少，UTF-8 编码，非空。
4. 每个文件都要写完整，不能停在半句话、未闭合的引号或括号里。写完后检查文件末尾。
5. YAML、JSON 产物必须符合工作单给出的 schema，不要用 Markdown 代码块包裹。
6. 最后写 `out_dir/receipt.json`（`schema: nv.receipt/1`）：
   - `status`：`done`、`blocked` 或 `failed`；
   - `artifacts`：逐条列出你写的文件，每项形如 `{ "path": "plan/compass.yaml" }`；
   - `nonces`：原样列出你在系统提示中看到的所有 `NV-` 开头的标记，只从系统提示抄录，不要去文件里找；
   - 工作单要求自报字数时，在 `self_count` 中填实测值。
7. 标准输出只是日志，不会被当作正文。正文和结构化结果都只以文件为准。
8. 无法完成时（缺少必要输入、硬性要求互相矛盾），把 `status` 设为 `blocked`，在 `questions_for_planner` 写明原因和你需要的信息，不要交付凑数的内容。
